Git拥有local repository和remote Repository
前者为本地存储，后者为云端存储。

# git init
将文件夹进行初始化，用git管理起来，变成git仓库
会生成一个不会显示的.git文件，用于对仓库的管理。最好在初始化阶段便将gitignore给确定好。

# .gitignore
在仓库根目录中建立的文件。声明了仓库中哪些不受到git的管理，如不会被git上传什么的。
.env 存储了密钥，即可加入到文件中避免上传泄露。
如果想要避免一整个目录上传，则在文件名后加/，即可让整个目录被排除在外。
## node_modules
存放了所有第三方依赖包。因为可以使用npm install随便下载所以通常也会加入到gitignore中避免被下载。

# 回退
## discard changes
当文件还没有commit时，通过这个来进行撤销。
## reset
把仓库强制回退到某个历史状态，一般用于单人使用的分支还未提交远端仓库。如果被撤销后的改动已经被上传过远端仓库，reset后则必须使用强制推送来覆盖远端仓库，有概率搞丢代码，多人合作时一般不会使用这一功能。

## revert
通过生成反向commit来抵消某次commit，适用于多人协作的分支，相对比较安全。

# Commit ID
git通过哈希算法，每次提交都会生成一个数字与字母混合的id，为仓库中绝对唯一的存在。

# fork
复制一份其他人仓库的代码到自己的仓库中。
# Branch
git通过指针来实现的不同开发路线。适用于多人开发，分别开发属于自己的功能，等调试完成后merge到主干之中。可以在分支的基础上创建分支，默认为按照当前提交进行的分支，也可以选择历史的提交。
## Head
会显示当前仓库处于哪一次commit上。

# git clone
将网上的仓库内容扒到本地。
# git push
将本地的内容上传到仓库。

# 快捷键
`\`可以快速打开github的搜索功能
`T`可以快速定位到文件搜索栏
`L`可以快速定位到行号
`?`可以打开快捷键的速查表
`.`可以打开一个内置的网页版vscode
# VS Code
## Graph
可以查看历史链路，展开commit后可以看到提交时的情况。通过点击checkout（detach）分离头指针功能就会让仓库回退到选择的历史版本。不推荐在detach里面修改代码，因为其当前不处于任何一个分支的管理中，在这个里面修改容易丢失代码。

## branch
可以在左下角进行分支的查看与更改

## commit
会同时执行git add和git commit的操作。通过点击加号来将文件添加到暂存区，如果没有选择文件添加到暂存区，则默认为commit所有文件。
